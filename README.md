# 한랭 (hanlang)

한국어로 읽히는 교육용 프로그래밍 언어. **컴파일러도 한랭으로 짜여 있다** — x86-64 어셈블리를 뱉고 gcc로 링크한다.
인터프리터가 아니라 **진짜 네이티브 실행파일**이 나온다.

```
학생 이란 묶음 {
    이름은 문자.
    점수는 정수.
}

반은 []이다.
반에 (새 학생)을 넣다.
(반의 1번째)의 이름은 "세준"이다.
(반의 1번째)의 점수는 95이다.

만약 (((반의 1번째)의 점수) >= 90) 라면 {
    ((반의 1번째)의 이름)을 끝"(이)가 " 말하다.
    "1등!"이라고 말하다.
}
```

조사가 인자 이름표 노릇을 한다. `가와 나를 더하다` 로 정의하면 `3과 4를 더하다` 로 부른다.

## 빠른 시작

```bash
make                        # 컴파일러 빌드 (gcc 만 있으면 됨)
./han examples/demo.han     # 한 번에 컴파일하고 실행
make test                   # 회귀 테스트 전부 돌리기
```

실행파일만 만들려면:

```bash
./hanc 프로그램.han -o 프로그램
./프로그램
```

## 설치

```bash
sudo make install           # 기본 /usr/local
han 프로그램.han
```

지울 때는 `sudo make uninstall`. 설치 위치는 `make install PREFIX=~/.local` 처럼 바꿀 수 있고,
라이브러리 폴더는 `HAN_LIB` 환경변수로도 지정할 수 있다.

## VSCode

```bash
make vscode          # 한랭 확장(.vsix)을 만들어 설치
```

문법 색칠, 저장할 때 오류·경고 밑줄(hanc 의 캐럿 자리 그대로), ▶ / `F5` 실행, 키워드에 마우스를 올리면 설명,
코드 조각(`만약`, `동안`, `함수`, `사전` …). 자세한 건 [editors/vscode/README.md](editors/vscode/README.md).
확장 없이도 이 폴더를 열면 `Ctrl+Shift+B` 로 실행된다.

## 뭐가 되나

- 타입: 정수 / 소수 / 문자 / 목록 / 격자(2차원) / 묶음(구조체)
  - 목록 안에 목록, 묶음 안에 묶음·목록, `없음` — 나무(트리) 같은 자료구조를 만들 수 있다
  - 사전: `점수표의 "철수"는 85이다.` — 이름표로 찾기 (해시표)
- 파일 읽기·쓰기: `파일 "a.txt"를 읽기로 열다 { 줄은 듣다. }` — 블록이 끝나면 저절로 닫힌다
- 명령줄 인자 `(명령줄)`, 종료코드 `1로 종료하다.`, 표준 에러 `파일 오류를 쓰기로 열다`, 못 연 경우 `못 열면 { }`
- 환경변수 `("HOME"의 환경값)`, 실제 경로 `(경로의 실제경로)`, `(실행파일)`, 다른 프로그램 `("ls"를 실행하다)`
- 시간 `(지금시각)` · `2초 기다리다.`, 정규식 `(글에서 "[0-9]+"를 맞추다)`, 창에 그리기 `창 640과 480을 열다.` (한글 글자도)
- 쓰레기 수거(GC)가 있어서 오래 돌아도 메모리가 안 분다
- 함수: 타입을 안 적어도 되고, **인자 타입마다 알아서 따로 만들어진다**
  (같은 `정렬하다` 가 정수 목록에도 문자 목록에도 동작)
- 반복 제어 `멈추다` / `계속하다`, 몫 `~/`, 비트 연산 `& | ^ ~ << >>`
- 문자↔코드값 `("가"의 코드)` / `(65의 글자)` — 한글도 한 글자로 센다
- `"정렬.han"을 불러오다.` 로 라이브러리 가져오기 — 13개 파일 150개 함수가 있고,
  **전부 한랭으로 짜여 있어서 열어 읽을 수 있다**
- 범위 밖 접근, 0 나누기 등은 실행 중에 잡아서 한국어로 알려준다

**에러 메시지가 이 언어의 핵심 기능이다.** 한국어로, 소스 줄과 캐럿과 고치는 법까지 나온다:

```
[오류] 3행: '나이' 는 정수 변수인데 소수를 넣으려 함. 처음부터 소수로 쓰려면 0.0 처럼 만들기
  3 | 나이는 3.5이다.
    | ^^^^
```

### 한랭 컴파일러는 한랭으로 짜여 있다

[compiler/한랭.han](compiler/한랭.han) 이 컴파일러 전체다 (약 3600줄, 한 파일).
렉서 → 불러오기 → 조사 분리기 → 파서 → 타입 검사기 → 코드 생성 순서로 읽으면 된다.
그리고 **자기 자신을 컴파일한다** — 그렇게 나온 컴파일러가 다시 자기 자신을 컴파일해도 어셈블리가 바이트 하나 안 다르다.

닭과 달걀 문제는 [bootstrap/hanc.s](bootstrap/hanc.s) 로 푼다. 컴파일러가 자기 자신을 컴파일해 둔 어셈블리라서
`make` 는 이걸 gcc 로 링크만 한다. 컴파일러를 고쳤으면:

```bash
make bootstrap      # 새 컴파일러로 자기 자신을 두 번 컴파일해 고정점을 확인하고 bootstrap/hanc.s 를 바꿈
```

처음엔 C++ 로 짠 `hanc.cpp` 가 있었고 한랭 판은 그걸 옮긴 것이었다. 둘이 모든 예제·테스트에서 출력과
에러 메시지까지 똑같이 도는 걸 확인한 뒤 C++ 판은 지웠다. 그때 옛 컴파일러가 낸 결과는
`tests/expected/` 에 정답으로 남겨서, 지금도 `make test` 가 글자 단위로 비교한다.

런타임(쓰레기 수거·목록·사전·입출력·창)은 [runtime/](runtime/) 의 C·어셈블리이고 `make` 가 `runtime/runtime.s` 로 굽는다.

## 파일

| | |
|---|---|
| `compiler/한랭.han` | 컴파일러 전체 (한랭으로 작성) |
| `bootstrap/hanc.s` | 컴파일러가 자기 자신을 컴파일해 둔 것 (`make` 가 링크) |
| `runtime/` | 런타임: `core.c`(GC·입출력·사전·시간·정규식), `window.c`(창), `helpers.s`(목록·문자 도우미) |
| `han` | 컴파일하고 바로 실행하는 스크립트 |
| `lib/*.han` | 표준 라이브러리 13개 (전부 한랭으로 작성) |
| `tests/` | 회귀 테스트 (`make test`). `t_*` 는 돌려서 `expected/` 와 출력 비교, `e*` 는 컴파일 에러(문구까지 비교) |
| `editors/vscode/` | VS Code 확장 (`make vscode`) |

## 아직 안 되는 것
