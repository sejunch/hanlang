# 한랭 (hanlang)

한국어로 읽히는 교육용 프로그래밍 언어. **컴파일러도 한랭으로 짜여 있다** — x86-64 어셈블리를 뱉고 gcc로 링크한다.
인터프리터가 아니라 **진짜 네이티브 실행파일**이 나온다.

```
학생 이란 묶음 {
    이름은 문자.
    점수는 정수.
}

반은 []이다.
반에 (새 학생)을 넣다.
(반의 1번째)의 이름은 "세준"이다.
(반의 1번째)의 점수는 95이다.

만약 (((반의 1번째)의 점수) >= 90) 라면 {
    ((반의 1번째)의 이름)을 끝"(이)가 " 말하다.
    "1등!"이라고 말하다.
}
```

조사가 인자 이름표 노릇을 한다. `가와 나를 더하다` 로 정의하면 `3과 4를 더하다` 로 부른다.

## 빠른 시작

```bash
make                        # 컴파일러 빌드 (gcc 만 있으면 됨)
./han examples/demo.han     # 한 번에 컴파일하고 실행
make test                   # 회귀 테스트 전부 돌리기
```

실행파일만 만들려면:

```bash
./hanc 프로그램.han -o 프로그램
./프로그램
```

## 설치

```bash
sudo make install           # 기본 /usr/local
han 프로그램.han
```

지울 때는 `sudo make uninstall`. 설치 위치는 `make install PREFIX=~/.local` 처럼 바꿀 수 있고,
라이브러리 폴더는 `HAN_LIB` 환경변수로도 지정할 수 있다.

## VSCode

```bash
make vscode          # 한랭 확장(.vsix)을 만들어 설치
```

문법 색칠, 저장할 때 오류·경고 밑줄(hanc 의 캐럿 자리 그대로), ▶ / `Ctrl+F5` 실행, `F5` 디버거(멈춤점·한 줄씩·변수 보기),
자동완성(변수·함수 — 조사 붙은 부르는 꼴까지·`수학의 …`·묶음 칸·키워드), 키워드에 마우스를 올리면 설명,
코드 조각(`만약`, `동안`, `함수`, `사전` …). 자세한 건 [editors/vscode/README.md](editors/vscode/README.md).
확장 없이도 이 폴더를 열면 `Ctrl+Shift+B` 로 실행된다.

## 뭐가 되나

- 타입: 정수 / 소수 / 문자 / 목록 / 격자(2차원) / 묶음(구조체)
  - 목록 안에 목록, 묶음 안에 묶음·목록, `없음` — 나무(트리) 같은 자료구조를 만들 수 있다
  - 사전: `점수표의 "철수"는 85이다.` — 이름표로 찾기 (해시표)
  - `아니면 만약`, `키에 따라 { "위" 라면 { } }`(여러 갈래), `번호를 늘리다.`, `점수의 2번째에 80을 넣다.`(끼워 넣기), 목록·사전 통째 말하기 `[1, 2]`
  - 전역 변수 `전역 점수는 0이다.`(그 파일 안), 블록 지역 변수 `지역 임시는 0이다.`
  - 함수를 값으로 `(큰순 함수)`·이름 없는 함수 `(가와 나로 { … })`, `(앞과 뒤를 기준으로 부르다)` · 변수 타입은 흐름 따라 바뀜
  - 실패 처리 `해보다 { } 안 되면 (까닭) { }`·`"…"라고 실패하다.` (실행 오류도 잡힘), 스레드 `(… F로 따로 부르다)`·`(일꾼을 기다리다)`·`(목록을 F로 나눠 부르다)`, 잠금 `잠금으로 잠그고 { }`
  - 벡터: `(1.0과 2.0과 3.0의 벡터)` — 평면·공간 벡터, `+ - * /`·내적·외적·길이·방향 (GPU 안에서도)
- 파일 읽기·쓰기: `파일 "a.txt"를 읽기로 열다 { 줄은 듣다. }` — 블록이 끝나면 저절로 닫힌다
- 명령줄 인자 `(명령줄)`, 종료코드 `1로 종료하다.`, 표준 에러 `파일 오류를 쓰기로 열다`, 못 연 경우 `못 열면 { }`
- 환경변수 `("HOME"의 환경값)`, 실제 경로 `(경로의 실제경로)`, `(실행파일)`, 다른 프로그램 `("ls"를 실행하다)`
- 시간 `(지금시각)` · `2초 기다리다.`, 정규식 `(글에서 "[0-9]+"를 맞추다)`, 인터넷 요청(https)
- 창에 그리기 `창 640과 480을 열다.` (한글 글자도) — 실시간 게임(`다시그리다.`, 키 `(눌린키들)`·`("위"를 누르고있나)`,
  마우스 `(마우스위치)`, 크기 바뀌는 창), 삼각형·픽셀로 3D
- GPU: 한랭 함수를 그대로 GPU 에서 수십만 번 동시에 (`"GPU.han"` — 컴파일러가 SPIR-V 로 번역, Vulkan)
- VS Code 디버거: 멈춤점, 한 줄씩, 함수 안/밖, 변수·전역·호출 스택
- 쓰레기 수거(GC)가 있어서 오래 돌아도 메모리가 안 분다
- 함수: 타입을 안 적어도 되고, **인자 타입마다 알아서 따로 만들어진다**
  (같은 `정렬하다` 가 정수 목록에도 문자 목록에도 동작)
- 반복 제어 `멈추다` / `계속하다`, 몫 `~/`, 비트 연산 `& | ^ ~ << >>`
- 문자↔코드값 `("가"의 코드)` / `(65의 글자)` — 한글도 한 글자로 센다
- `"정렬.han"을 불러오다.` 로 라이브러리 가져오기 (`자료를 정렬의 빠르게정렬하다.` 처럼 파일 이름을 붙여 부르는 이름공간,
  별명·골라 불러오기도 됨) — 17개 파일 149개 함수가 있고,
  **전부 한랭으로 짜여 있어서 열어 읽을 수 있다**
- 범위 밖 접근, 0 나누기 등은 실행 중에 잡아서 한국어로 알려준다

**에러 메시지가 이 언어의 핵심 기능이다.** 한국어로, 소스 줄과 캐럿과 고치는 법까지 나온다:

```
[오류] 1행: '*' 는 숫자끼리만 됨
  1 | 수를 두배로 란 { (수 * 2)를 돌려주다. }
    |                      ^
  '두배로' 를 3행에서 부름 (인자: 문자)
```

### 한랭 컴파일러는 한랭으로 짜여 있다

[compiler/한랭.han](compiler/한랭.han) 이 컴파일러 전체다 (약 7300줄, 한 파일 — GPU 용 SPIR-V 번역기까지).
렉서 → 불러오기 → 조사 분리기 → 파서 → 이름 정리(전역·지역) → 타입 검사기 → 코드 생성 순서로 읽으면 된다.
그리고 **자기 자신을 컴파일한다** — 그렇게 나온 컴파일러가 다시 자기 자신을 컴파일해도 어셈블리가 바이트 하나 안 다르다.

닭과 달걀 문제는 [bootstrap/hanc.s](bootstrap/hanc.s) 로 푼다. 컴파일러가 자기 자신을 컴파일해 둔 어셈블리라서
`make` 는 이걸 gcc 로 링크만 한다. 컴파일러를 고쳤으면:

```bash
make bootstrap      # 새 컴파일러로 자기 자신을 두 번 컴파일해 고정점을 확인하고 bootstrap/hanc.s 를 바꿈
```

처음엔 C++ 로 짠 `hanc.cpp` 가 있었고 한랭 판은 그걸 옮긴 것이었다. 둘이 모든 예제·테스트에서 출력과
에러 메시지까지 똑같이 도는 걸 확인한 뒤 C++ 판은 지웠다. 그때 옛 컴파일러가 낸 결과는
`tests/expected/` 에 정답으로 남겨서, 지금도 `make test` 가 글자 단위로 비교한다.

런타임(쓰레기 수거·목록·사전·입출력·정규식 …)도 한랭으로 짰다: [runtime/기본.han](runtime/기본.han).
메모리를 직접 만지고 libc 함수를 부르는 낮은 수준 기능(파일 맨 위 `낮은수준을 쓰다.`)을 쓰고,
`make` 가 `hanc --모듈` 로 구워 어셈블리 몇 줄([runtime/helpers.s](runtime/helpers.s))과 함께 `runtime/runtime.s` 로 만든다.
C 는 한랭으로 못 짜는 곳에만 남아 있다: 실패·스레드([runtime/thread.c](runtime/thread.c) — setjmp·스레드마다 따로인 칸·pthread), 창(X11, [runtime/window.c](runtime/window.c)),
GPU(Vulkan, [runtime/gpu.c](runtime/gpu.c)), 디버거와 주고받기([runtime/debug.c](runtime/debug.c)).
창·GPU·디버거는 그 기능을 쓰는 프로그램에만 붙는다.

컴파일러는 자주 쓰는 변수를 레지스터에 두고, 비교는 바로 분기하고, 목록 칸 읽기·쓰기를 그 자리에 펼치고,
작은 함수를 펼치고 상수를 미리 계산한다. 대략 C 를 최적화 없이(-O0) 컴파일한 정도의 속도가 나온다.

## 웹 놀이터

[playground/](playground/) — 브라우저에서 바로 돌려 보는 페이지와 서버. 서버는 진짜 hanc 로 컴파일해서 돌리고,
서버를 지키려고 `hanc --놀이터` 로 `실행하다`·낮은 수준·GPU 를 막고, 파일은 실행마다 새로 만든 폴더 안만 연다.
Google Cloud 무료 VM 에 올리는 스크립트는 [playground/gcp/](playground/gcp/).

```bash
python3 playground/server.py      # http://localhost:7860
```

Hugging Face Spaces(Docker)에 올리는 파일은 [playground/space/](playground/space/) 에 있다.

## 아직 안 되는 것

- 리눅스 x86-64 만 된다 (윈도우는 첫 릴리즈 뒤에)
- 이름 없는 함수는 바깥의 지역 변수를 못 본다 (전역은 됨). 한 변수·목록에 서로 다른 함수 값을 번갈아 담을 수 없다
- 듣다는 문장으로만 (`이름은 듣다.`), 식 안에서는 못 쓴다
